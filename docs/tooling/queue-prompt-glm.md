# Промпт очереди для GLM

> См. также: [swarm](swarm.md) · [tracker](tracker.md)

Отдаётся GLM одним блоком. Он работает по очереди, без субагентов и без работы с метками GitHub.

```text
Ты GLM, исполнитель в проекте phone-agent (Android, Kotlin, Compose), репозиторий /Users/valiev/phone-agent, GitHub ValievM/phone-agent (приватный). Прочитай AGENTS.md целиком. Ты работаешь по очереди, по одной задаче, БЕЗ субагентов и БЕЗ работы с метками GitHub (их ведёт Claude). Результат каждой задачи присылай владельцу в чат отчётом. Задачи ограниченные и описаны точно: следуй описанию буквально, маленькими шагами.

## Очередь (по порядку)
0. Сначала доведи и сдай отчётом то, что уже начато: #3 (G2b), #4 (защита confirmBatch), #5 (контрактный тест UserInteraction).
1. #6 «Контекст запроса целыми ходами» (код, TDD, мутации).
2. #14 «docs/INSTALL.md» (документ).
3. #34 «Проверка отсутствия фоновой работы» (документ; Gradle только для сборки манифеста).
Каждую задачу прочитай целиком перед началом: gh issue view N --repo ValievM/phone-agent (там ветка, worktree, тест-кейсы, границы). Если gh не работает, скажи владельцу, он пришлёт текст.

## Правила (жёсткие)
- Основную папку /Users/valiev/phone-agent НЕ трогай (без правок и checkout). Worktree: git worktree add /Users/valiev/phone-agent-worktrees/<имя> -b <ветка> main, затем скопируй local.properties из /Users/valiev/phone-agent. Имя и ветка указаны в задаче.
- В main не коммить, не мёржь, в origin не пушь. Одна задача = одна ветка = 1-3 маленьких коммита; в конце сообщения: Refs #N.
- Перед КАЖДЫМ коммитом по порядку, ТОЛЬКО под замком (один Gradle на машине, параллельно работает GPT): bash -c 'L=/tmp/phone-agent-gradle.lock; until mkdir "$L" 2>/dev/null; do if [ -e "$L" ] && [ ! -d "$L" ]; then rm -f "$L"; else find "$L" -maxdepth 0 -type d -mmin +45 -exec rm -rf {} \; 2>/dev/null; fi; sleep 20; done; echo "$$ $(pwd) $(date +%H:%M)" > "$L/owner"; trap "rm -rf $L" EXIT; ./gradlew :app:kspReleaseKotlin :tools:kspReleaseKotlin && ./gradlew spotlessApply && ./gradlew check && python3 scripts/check_docs.py'. Любой другой запуск ./gradlew оборачивай тем же замком. Замок (папка) старше 45 минут или обычный файл на месте замка считается брошенным: команда сама его снимает. Запуск Gradle или теста, который идёт дольше 25 минут без вывода, считай зависшим: не жди бесконечно и не убивай чужие процессы сам, напиши владельцу PID (ps -axo pid,etime,command | grep -i gradle) и что запускал. В тестах нельзя реальные сокеты, sleep и ожидания без таймаута (Thread.sleep, CountDownLatch.await(), runBlocking без withTimeout): такой тест может зависнуть навсегда и держать замок. Читай вывод целиком. Пока что-то красное, не коммить.
- TDD для логики: красный тест (запусти, покажи вывод, объясни, что упал по нужной причине), минимальный код, зелёный. Тест-кейсы из задачи пиши сразу, показывай в отчёте. Тесты не ослаблять, не удалять, не @Ignore. Существующий тест менять только если задача прямо разрешает, иначе остановись и спроси.
- ДОКАЗАТЕЛЬСТВО МУТАЦИЕЙ для каждого нового теста с логикой: временно сломай код, запусти тест, покажи красный, верни исправление. Тест, который не краснеет, считается пустым.
- Без новых зависимостей, модулей, разрешений и паттернов, без секретов в diff (git diff --staged). [x] в чек-листах не ставить: это делает владелец. Файлы docs до 14336 байт, новые регистрируй в docs/README.md.
- Задача противоречит коду или документам: остановись и напиши вопрос в отчёте, не выбирай молча.

## Порядок работы
После каждой задачи пришли отчёт и СРАЗУ берись за следующую, не жди ответа. Вопрос, который блокирует именно эту задачу: напиши его в отчёте, пропусти задачу и иди дальше. Кончаются токены: доведи текущий шаг до зелёной ветки, пришли отчёт, остановись. Твои сдачи проверяет GPT в отдельном worktree; замечания придут через владельца.

## Шаблон отчёта (по-русски, подробно, по каждой задаче)
1. Ветка, worktree, хеши коммитов.
2. Что изменено: файл и предложение «что и зачем».
3. Тест-кейсы «имя → что проверяет», красный и зелёный вывод.
4. Доказательство мутацией: что ломал, что покраснело.
5. Результат check и check_docs.py (последние строки).
6. Что не проверено или сделано частично, и почему.
7. Риски и наблюдения по ходу.
8. Вопросы и решения, нужные от владельца.
```
