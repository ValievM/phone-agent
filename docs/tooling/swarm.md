# Рой GPT и очередь GLM

> См. также: [tracker](tracker.md) · [AGENTS.md](../../AGENTS.md) · [OWNER-TASKS.md](../../OWNER-TASKS.md)

Только GPT работает роем: сам разбирает очередь из GitHub Issues, запускает субагентов, проверяет работу независимым субагентом и не простаивает. GLM работает по очереди, по одной задаче, без субагентов и без работы с метками: метки и комментарии за него ведёт Claude, отчёты GLM присылает владельцу в чат. Оба берут одни и те же issues (в каждой полное описание задачи).

## Схема
| Шаг | Кто | Метки после шага |
|---|---|---|
| Задача заведена и готова | Claude | `who:gpt` или `who:glm` + `status:ready` |
| **GPT:** захват и работа (субагенты в своих worktree) | GPT | `status:doing` |
| **GPT:** независимая проверка своей сдачи субагентом-проверяющим | GPT | затем `who:claude` + `status:review` |
| **GLM:** работа по очереди, отчёт в чат | GLM | метки ведёт Claude |
| **GLM:** сдача GLM уходит на проверку GPT | Claude | `who:gpt` + `status:review` |
| Проверка сдачи GLM в отдельном worktree | GPT | OK: `who:claude` + `status:review`; замечания: `who:glm` + `status:doing` (Claude передаст их GLM) |
| Ревью, слияние по слову владельца, закрытие | Claude | issue закрыт |
| Вопрос или блокировка | GPT | `who:claude` + `status:blocked` |

Записки («Записка: …») GPT сразу передаёт Claude без перекрёстной проверки. Задачи с `who:owner` и `who:claude` не берёт никто из агентов.

## Границы
- GPT меняет только метки `who:`, `status:` и пишет комментарии в issues своей очереди и своих проверок; комментарии начинаются с `[GPT]` (действия идут от аккаунта владельца).
- Закрывать issues, вливать ветки, пушить в `origin`, создавать и удалять issues и метки может только Claude по слову владельца.
- Gradle на машине запускается только под замком, один запуск за раз (GPT, GLM и Claude): параллельные сборки уже давали флаки.
- Субагентов не больше 3; токены расходуются быстрее, поэтому сначала задачи с меткой `mvp`.
