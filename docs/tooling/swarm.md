# Команда: GPT-1, GPT-2, GLM, Claude и владелец

> См. также: [tracker](tracker.md) · [AGENTS.md](../../AGENTS.md) · [OWNER-TASKS.md](../../OWNER-TASKS.md)

Пять участников. Оба GPT работают роем: сами разбирают свою очередь из GitHub Issues, запускают субагентов и проверяют друг друга. GLM работает по очереди, по одной задаче, без субагентов и без работы с метками (их ведёт Claude, отчёты GLM присылает владельцу в чат). Все берут issues с полным описанием задачи.

## Кто за что отвечает (зоны кода)
| Участник | Метка | Зона | Что делает |
|---|---|---|---|
| **GPT-1** | `who:gpt1` | логика: `:core:domain`, `:tools`, `:data:llm`, `:data:auth` | цикл агента, инструменты, протокол, состояние хода |
| **GPT-2** | `who:gpt2` | интерфейс: `:app`, экраны, дизайн-система | экраны, карточки, шторки, вид «Стыка» |
| **GLM** | `who:glm` | тесты, инфраструктура, документы | контрактные тесты, правила `ArchitectureTest`, доки, мелкий техдолг |
| **Claude** | `who:claude` | интеграция и релиз | финальное ревью, слияния, CI, проверка протокола, релиз, замеры |
| **Владелец** | `who:owner` | решения и телефон | решения, проверка на телефоне, дизайн, ключ подписи |

Зоны нужны, чтобы меньше конфликтовать при слиянии: задача из чужой зоны допустима, но правится минимально. Пересечение зон (например `ToolPipeline` и экран чата) решает Claude при слиянии.

## Кто кого проверяет
| Автор | Проверяет | Потом |
|---|---|---|
| GPT-1 | GPT-2 | Claude |
| GPT-2 | GPT-1 | Claude |
| GLM | GPT-1 (логика, тесты) или GPT-2 (интерфейс), назначает Claude | Claude |

Записки («Записка: …») и задачи с пометкой «проверяет Claude» сразу идут к Claude.

## Схема меток
| Шаг | Кто | Метки после шага |
|---|---|---|
| Задача заведена и готова | Claude | `who:gpt1`, `who:gpt2` или `who:glm` + `status:ready` |
| **GPT:** захват и работа (субагенты в своих worktree) | GPT-N | `status:doing` |
| **GPT:** сдача на проверку другому GPT | GPT-N | `who:gptM` + `status:review` |
| Проверка чужой сдачи в отдельном worktree | GPT-M | OK: `who:claude` + `status:review`; замечания: автору + `status:doing` |
| **GLM:** работа по очереди, отчёт в чат | GLM | метки ведёт Claude |
| **GLM:** сдача уходит на проверку GPT | Claude | `who:gpt1` или `who:gpt2` + `status:review` |
| Ревью, слияние по слову владельца, закрытие | Claude | issue закрыт |
| Вопрос или блокировка | GPT | `who:claude` + `status:blocked` |

Задачи с `who:owner` и `who:claude` агенты не берут.

## Границы
- GPT меняет только метки `who:`, `status:` и пишет комментарии в issues своей очереди и своих проверок; комментарии начинаются с `[GPT-1]` или `[GPT-2]` (действия идут от аккаунта владельца).
- Закрывать issues, вливать ветки, пушить в `origin`, создавать и удалять issues и метки может только Claude по слову владельца.
- Gradle на машине запускается только под замком, один запуск за раз (все участники): параллельные сборки уже давали флаки. Замок держится на время одной проверки (около минуты), поэтому очередь к нему небольшая.
- Субагентов не больше 2 у каждого GPT (вместе не больше 4); токены расходуются быстрее, поэтому сначала задачи с меткой `mvp`.
- Узкое место это финальное ревью Claude: чем больше сдач, тем длиннее очередь на него. Поэтому проверка другим GPT обязательна до Claude.
