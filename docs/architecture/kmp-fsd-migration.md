# План перехода на KMP и FSD

См. [ADR 0008](../adr/0008-kmp-fsd.md). Оценка по размеру кода и нашему темпу (≈ 6–8 задач в день); это ориентир, не обещание.

| Этап | Что | Задач | Риск |
|---|---|---|---|
| 0 | ADR, каркас слоёв-модулей, правила Konsist, проба на ядре | 2–3 | низкий |
| 1 | `:core:domain` → `:entities` + `:shared` в KMP: убрать `java.time`/`UUID`/`Locale`, тесты на `kotlin.test` | 5–7 | низкий (механика) |
| 2 | Сеть и вход на Ktor; интерфейс хранилища токена, реализация в `androidMain` | 8–12 | **высокий**: SSE, отмена |
| 3 | Room KMP, DataStore KMP, миграция схемы | 4–6 | средний |
| 4 | Фичи по слайсам (чат, голос, инструменты, вход, настройки) вместе с тестами | 15–25 | средний |
| 5 | Compose Multiplatform и оболочка iOS (только по решению владельца) | 25–45 | высокий |

Итого общий слой и фичи (этапы 0–4): ≈ 35–55 задач. Этап 5 отдельно.

## Целевая структура
```
:app        entry, DI (Hilt), navigation, theme            (androidMain)
:screens    Chat, Settings, About, Login                   (pages)
:widgets    Composer, MessageList, ApprovalSheet, VoiceBar
:features   send_message, voice, approve_call, share, ...  (model + ui + api)
:entities   message, tool_call, conversation, ...          (domain models + ports)
:shared     ui-kit (design system), api (Ktor), lib, config
```
Правила: модуль зависит только от модулей ниже (Gradle); слайсы одного слоя не импортируют друг друга (Konsist); `commonMain` без Android-типов; адаптеры платформы в `androidMain`.

## Правила переноса среза
Срезы вливаются в `dev` (стабильная версия отдельно: `release/0.1`). Один срез = одна фича/сущность целиком (код + тесты), приложение собирается и тесты зелёные на каждом шаге; старый код удаляется в том же срезе; новые Konsist-исключения только временные и перечислены в списке, который уменьшается.

## Каркас

Этап 0 добавляет Gradle-модули слоёв, правила границ и KMP-конвенцию, не перенося существующий код. Новая структура включена в `settings.gradle.kts`:

| Модуль | Назначение | Может зависеть от |
|---|---|---|
| `:screens` | Экранная композиция | `:widgets`, `:features`, `:entities`, `:shared` |
| `:widgets` | Повторно используемые UI-блоки | `:features`, `:entities`, `:shared` |
| `:features` | Независимые пользовательские слайсы | `:entities`, `:shared` |
| `:entities` | Общие бизнес-сущности | `:shared` |
| `:shared` | Общие кросс-слойные контракты и утилиты | нет |

Слои — Kotlin Multiplatform библиотеки с целями `androidTarget` и `jvm`, без iOS-целей. Конвенция `phoneagent.kmp.library` задаёт `commonMain` и `commonTest`, подключает `kotlin.test`, explicit API, detekt и JDK 17. Spotless/ktlint применяется к исходникам общим корневым convention. Android target использует Android library plugin и публикует release-вариант для Android-потребителей (AGP 8.13).

`app` — composition root и может подключать все пять модулей. Остальные модули зависят только вниз по таблице. Когда появится настоящий слайс, добавляйте его как пакет внутри слоя (например, `com.example.phoneagent.features.voice`), а не как новый модуль без отдельного решения.

## Добавление слайса и зависимости

1. Создайте пакет `com.example.phoneagent.<слой>.<слайс>` и организуйте код по сегментам `ui`, `model`, `api`, `lib` или `config`, согласно решению о миграции KMP + FSD.
2. Общие для нескольких слайсов типы разместите в `entities` либо `shared`; не импортируйте другой слайс того же слоя.
3. Платформонезависимую реализацию помещайте в `commonMain`; platform-specific зависимости оставляйте вне него.
4. Измените зависимость Gradle только на слой ниже. Сборка не допускает обратных циклов, а Konsist отдельно запрещает импорты вышележащего слоя.
5. Запустите `check`: FSD-правила проверяются тестом `FsdLayersTest` в `:app`.

## Что защищают правила

- `FsdLayersTest` запрещает исходникам слоя импортировать пакеты любого слоя выше него (`screens`, `widgets`, `features`, `entities`, `shared`).
- Слайс `features.<имя>` не может импортировать пакет `features.<другой-слайс>`.
- В `commonMain` запрещены импорты `android.*`, `androidx.*` и `java.*`; для Android/iOS/JVM API нужны отдельные source sets либо платформонезависимые контракты. Сейчас разрешённых исключений нет.
- Направление проектных зависимостей выражено Gradle-графом: `screens → widgets → features → entities → shared`; `:app` является исключением как верхний composition root.

Пустые исходные файлы и тесты в новом каркасе фиксируют ожидаемые source sets; при переносе реального кода их можно удалить или заменить вместе с соответствующими проверками.
## Проба Ktor

Временный модуль `:probe:ktor` проверяет SSE-транспорт через CIO и `MockEngine`. Он не подключён к `:app` или релизу; парсер, mapper и DTO компилируются прямо из `data/llm/src/main`, без копирования или изменения боевого кода.
Краткая инструкция и причина выбора движка: [README модуля](../../probe/ktor/README.md).

| Сценарий | OkHttp (сейчас) | Ktor (проба) | Совпадает? | Что делать при миграции |
|---|---|---|---|---|
| Успешный стрим и границы строк | `readUtf8Line()` подаёт строки в общий `SseParser`; mapper переводит текст и завершение в `ModelEvent`. | `readUTF8Line()` подаёт строки в тот же parser и mapper. | Да | Оставить общий parser и mapper. |
| Комментарии, keep-alive, пустые и многострочные события | SSE parser игнорирует комментарии/пустые события и соединяет `data:` строками через `\n`; неизвестные события mapper игнорирует. | Используется тот же parser и mapper. | Да | Обёртка не нужна. |
| HTTP 4xx/5xx с телом | Отказ становится `ModelEvent.Failed`; тело читается только для безопасного резюме в логе, в событие не включается. | Статус становится `ModelEvent.Failed`, тело ответа не включается. | По типу ошибки и утечке тела — да; телеметрия не сравнивается. | Сохранить mapping статусов и безопасную обработку тела отдельно от потока. |
| Обрыв/ошибка посреди потока | `IOException` маппится в `Offline`, таймаут — в `Timeout`, как событие. | `MockEngine` выдаёт текстовое событие, затем закрытие канала с `IOException`; оба события получены в правильном порядке. | Да | Сохранить адаптер исключений Ktor → `AgentError`; не глотать отмену. |
| Отмена коллектора и повторный запрос | Коллектор отменяет OkHttp `Call`; следующий вызов клиента независим. | `HttpStatement.execute {}` закрывает response при отмене; MockEngine-тест подтверждает закрытое тело, повторный запрос на том же клиенте успешен. | Да | Всегда закрывать response структурно и сохранить повторный вызов на одном клиенте. |
| Таймаут | `SocketTimeoutException` становится `AgentError.Timeout`. | `HttpRequestTimeoutException` и `SocketTimeoutException` маппятся в `Timeout` через `MockEngine`. | Да для преобразования исключений; запуск реального таймера не моделировался. | Оставить явное преобразование timeout исключений. |

**Вывод:** можно мигрировать с тонкими обёртками — явным преобразованием HTTP-статусов и Ktor/IO-исключений в `AgentError` и структурным закрытием response; SSE-парсер и mapper переиспользуются без изменений. В тесте не моделировался реальный истёкший таймер, а только соответствующие исключения. Боевой код этой пробой не изменяется.
