# Замеры релиза 0.1

Скрипты в [`scripts/measure/`](../scripts/measure/) собирают данные с одного подключённого Android-устройства через Android Platform Tools (`adb`). Они не отправляют данные наружу. Для фоновой проверки закройте активный чат; телефон и эмулятор агент не подключает и сам замеры не запускает.

## Подготовка и запуск

1. Установите Android Platform Tools, включите отладку по USB, подключите телефон и подтвердите доверие компьютеру. `adb devices` должен показывать ровно одно устройство со статусом `device`.
2. Убедитесь, что установлено приложение с пакетом `com.example.phoneagent`. При необходимости задайте другой пакет через `PACKAGE=имя.пакета`.
3. Из корня репозитория запустите все замеры (по умолчанию ожидание батареи — 60 минут):

   ```bash
   scripts/measure/run-all.sh [минуты]
   ```

   Отчёт появится в `build/measure/<время>.md` (эта папка не предназначена для коммита). Отдельно можно запускать `mem.sh`, `battery.sh [минуты]`, `background.sh` и `startup.sh` из любого каталога. Скрипты требуют `adb` в `PATH` и ровно одно подключённое устройство; для каждого измерения проверяются оба условия.

`battery.sh` — единственный скрипт, сбрасывающий статистику телефона: `dumpsys batterystats --reset`. Он ожидает заданное количество минут; не запускайте его, если важно сохранить накопленную статистику батареи. `startup.sh` перед каждым холодным запуском выполняет `am force-stop com.example.phoneagent`; это разрешённое исключение, которое не удаляет данные приложения. Остальные скрипты только читают данные.

## Что измеряется

- **Память:** три значения TOTAL PSS из `dumpsys meminfo`, пауза между ними — 2 секунды по умолчанию (`SAMPLE_INTERVAL` меняет интервал). Результат в КБ, МБ и среднее.
- **Батарея:** процент заряда до ожидания и после, разница в процентных пунктах и запись UID приложения из `dumpsys batterystats --charged`, если ОС её вывела. Этап 6 задаёт сценарий «час простоя»; сравнивать следует при одинаковом сценарии и длительности. Отсутствие записи UID не означает нулевой расход.
- **Фоновая работа:** строки `jobscheduler`, `alarm`, `activity services` и `ps`, относящиеся к пакету. Ноль совпадений даёт `фоновых задач: 0`; найденные строки печатаются, код завершения ненулевой. Выполняйте без активного чата: процесс открытого приложения сам по себе не доказывает фоновую работу.
- **Запуск:** пять остановок и запусков через `am start -W`, времена `TotalTime` и среднее в миллисекундах.

## Как оценивать результаты

Критерии этапа 6 — это отсутствие фоновых служб, задач и будильников (кроме будильника, установленного пользователем через Часы) и отсутствие приложения в топе расхода батареи в простое. Для памяти этап 6 требует записать результаты сценариев простоя, стрима ответа и поиска файлов, но целевого порога в документах проекта нет. Численные нормы памяти и времени запуска не заданы; не считайте произвольный порог успешной приёмкой. См. также [фактические сведения и прежнюю проверку по коду/манифесту](measurements.md) и [критерии этапа 6](stages/6-release.md).

Отчёт содержит только пакет приложения, числовые результаты и отфильтрованные строки, содержащие его package name; не добавляйте к нему логи или снимки экрана с личными данными. Для окончательной оценки батареи учитывайте список потребителей в выводе `batterystats --charged`, а не только изменение общего процента заряда: оно зависит от всего устройства и длительности теста.
